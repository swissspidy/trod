Across fresh sessions: a library built once

Four fresh sessions (fresh checkouts, as with ephemeral cloud containers) against a quirky internal inventory API, each with a different question. The toolsmith arm first spends one dedicated session building robust, general tools (auth, paging, backoff, number parsing; examples that pass). The question sessions then use those tools without any nudge. Result: 0.74× baseline tokens, 22 vs 28 turns, and every run passed (the scripts and genesis arms each failed one). The toolsmith session costs about 386k tokens once and saves about 33k per later session, so it breaks even after about 12 sessions.

Tools built in passing did not transfer. Nudged sessions built answer-shaped tools that the next question could not use (1.31×), and leftover scripts saved 3%. The value comes from treating tools as an asset: built deliberately, tested, and reused many times.

The toolsmith investment

One dedicated session built the library before the measured sessions (mean of 3): 386k tokens, $0.186, 18 turns. Tools built: items_list.mjs, movements_list.mjs · inv_items.mjs · inv_items.mjs, inv_movements.mjs.

Each measured session with the library used 33k fewer tokens than baseline ($0.012 less). The investment pays for itself after 12 sessions (in tokens).
