trod · for Claude Code

Teach a small model your environment once.

trod runs one dedicated session that studies, or practises on, your API, tooling or workflow. It writes a verified tool library and short, rule-shaped notes. Every later session loads them, so a cheap model works like one that already knows the place.

Great fit

  • Internal or quirky APIs: auth, paging, soft deletes, units
  • Unfamiliar codebases and in-house tooling
  • Web and app workflows with hidden rules
  • Anything with a success check to practise against: tests, graders, smoke tests

Little or no effect

  • Domains the model already knows well (SWE-bench on Django: no change)
  • Tasks that each need a fact no earlier task taught (BIRD: tokens saved, accuracy flat)
  • Building tools mid-task instead of forging once: no cheaper than writing a script

How it works

Forge

trod forge runs a dedicated headless session with any model. It probes the environment, builds general tools with tested examples, and writes .trod/notes.md: rules a newcomer gets wrong, each with the action to take.

Learn

trod learn reads the transcripts Claude Code already keeps for your project, compares sessions that failed with ones that worked, and writes the rules that would have prevented the failures. No brief, no labels needed.

Practise

With --practice 'npm test' (or any command where exit 0 means success) the forge learns from real attempts. It must pass at least once, or its notes are not linked.

Reuse and verify

Tools whose examples pass go to .trod/library, and the notes are imported into CLAUDE.md, so every later session starts informed. trod verify in CI re-runs every example and note check to catch drift.

Underneath sits a live MCP tool server. The agent can write .trod/tools/<name>.mjs mid-session, and trod validates it, runs its examples and registers it without a restart.

trod lines up with Anthropic's findings on agent memory: keep the injected layer small, record validated rules rather than raw logs, and let an offline pass (their "dreaming", trod's forge) correct and consolidate. trod adds a success check that the knowledge must pass and paired measurements per environment. Install

Set up a repository for every Claude Code session in it, whether local, cloud or started from the Claude mobile app, then learn from the sessions you already had, or forge against something new:

npx trod init                       # .mcp.json, settings, skill; commit them
npx trod learn                      # notes from your past sessions
npx trod forge --brief @env.md --practice 'npm test'
npx trod verify                     # in CI

As a Claude Code plugin: claude plugin marketplace add swissspidy/trod, then claude plugin install trod@trod. In Antigravity: agy plugin install https://github.com/swissspidy/trod. Other MCP clients run npx -y trod mcp. Tool code runs outside Claude Code's permission prompts, so execution stays off in later sessions unless TROD_ALLOW_EXEC=1 is set (npx trod init --allow-exec); that is meant for ephemeral containers. See the reference for every install route.
