Verdict

Not on these tasks, with this model. Every session in every arm passed. Given trod, the agent almost never built a tool unprompted (1 of 24 repetitive sessions): it wrote a parameterized script in the first step and re-ran it in the follow-ups. A script on disk is already a tool. When the agent was required to build trod tools, sessions cost 1.84× baseline (15.8 vs 7.7 turns), even though each tool was reused 3–4 times.

The overhead does not stay in step 1. The tool-building turns remain in the resumed context and are read again on every later turn, so even the reuse steps cost about 1.8× baseline. Tools carried over from an earlier session broke even overall (0.98× cost, 1.15× turns). The agent usually read their source before trusting them. That paid off for a fiddly spec (Markdown links: 0.69×) and did not for an easy one (log analysis: 1.16×).

What would change it: cheaper creation (wrap the script the agent already wrote), no ToolSearch reload after a resume, examples that let later sessions trust a tool without reading it, and longer sessions with many small interleaved repetitions or pipelines that keep failing.
