# AppWorld rules

## Identity, auth, time
- "I/me/my" = the supervisor (apis.supervisor.show_profile). Log in to each app with the supervisor's password from show_account_passwords: phone uses phone_number as username, all other apps use email. Never sign up, reset passwords or log out.
- The world has a SIMULATED clock (e.g. 2023-05-18), not the real date. Take "today" from the REPL (datetime.now() / phone.get_current_date_and_time). "Last N days including today" = from today-(N-1) through today. "This year" = Jan 1 of the simulated year. "Last month" = the previous calendar month.
- Dates are ISO strings "YYYY-MM-DDTHH:MM:SS". API date filters take "YYYY-MM-DD". Compare dates on the first 10 chars.

## Fetching
- List/search APIs are paginated (page_index from 0, page_limit default 5, max 20). Always loop until a page is short or empty. Never conclude something is absent from one page.
- A `query` parameter only RANKS results; it never excludes anything (a nonsense query still returns everyone). Always filter by the exact field locally.
- Failures come back as {"message": ...}, which looks the same as a successful write's {"message": ...}. Pass raise_on_failure=True (or check the message text) and treat errors as failures, not done.

## People and relationships
- Relationships ("my friends", "roommates", "coworkers", "manager", "family", "sister") come ONLY from phone contacts' `relationships` field (singular, lowercase; phone.search_contacts with relationship=...). Do NOT use Venmo friend lists, Splitwise groups or email threads to decide who is a friend, roommate or coworker. Train tasks failed exactly this way.
- A contact's email is that person's account in venmo, splitwise, gmail, spotify and amazon. Their phone_number is used for texts and voice messages. Match records by email, not by display name.
- With several relationships ("friends and roommates"), take the union. If nobody has a relationship, nobody qualifies; do not substitute.

## Scope and side effects
- Act on exactly the records the task selects: all of them, nothing else. Skip records already in the target state (already liked, already following, already completed). Do not touch other data: no extra queueing, friending, messages, notes or deletions.
- Use the user's own collections when the task says "my" (Spotify "my playlists" = show_playlist_library). Do not fall back to public catalog items unless asked.
- Venmo: received payment requests = others asking the user for money (approve_payment_request or deny_payment_request by payment_request_id; filter status="pending"). "Payments I received" = show_transactions direction="received". Likes and comments target transaction_id.
- Splitting a bill "equally among roommates and me" means share = round(total/(n+1)) (whole dollars), one request per roommate. Use the description text the task gives, verbatim.
- Spotify: song duration is in SECONDS. A playlist's length = sum of its songs' durations (show_song). "Enough for a workout of M minutes" means total >= M*60. play_music(playlist_id=...) REPLACES the queue with that playlist. Play exactly one qualifying playlist from the user's library (the first in library order) and queue nothing else.
- Simple Note workout plans hold blocks of "day: <weekday>" ... "duration_mins: N". Use the block for today's weekday. When editing a note, change only the needed substring and keep the rest of the content verbatim.
- Phone alarms: time is "HH:MM" (24h). Labels like "Wake Up" or "Go to sleep" identify alarms; change only the fields asked.
- Todoist tasks are nested in projects and sections (project_id 0 = Inbox). Overdue = due_date before now and not completed. The API's overdue=True filter can crash; compute it locally.

## Finishing
- Call apis.supervisor.complete_task(answer=...) once at the end. Give an answer only for questions, and keep it minimal: the bare title, name or number (e.g. 42, not "$42.00 total"). For action tasks, leave answer=None.
