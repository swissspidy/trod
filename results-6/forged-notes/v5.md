# AppWorld notes

## Runtime
- REPL state persists. Its `print` JSON-dumps objects (tuple-keyed dicts crash it). Use getattr(apis, "spotify").
- Clock is SIMULATED (e.g. 2023-05-18 12:00): use REPL datetime.now() / phone.get_current_date_and_time, never the real date. "Today's workout" = simulated weekday.
- Failed calls usually RETURN {"message": ...} instead of raising; check for it. todoist show_tasks(overdue/due_today=True) raises when any task has due_date null: filter locally.

## Auth
- supervisor.show_profile() (name, email, phone_number) + show_account_passwords() [{account_name,password}].
- login(username, password): phone uses the PHONE NUMBER, all other apps the email. access_token on every user-scoped call; api_docs, supervisor, public catalog (spotify.show_song, search_*) need none.

## Pagination
- page_index (0-based) + page_limit (default 5, MAX 20). Loop until a short page; one call silently misses data. Not paged: file_system.show_directory, todoist.show_tasks (needs project_id; 0 = Inbox), spotify.show_song_queue, amazon.show_cart.
- query search is fuzzy relevance-ranked (returns unrelated rows: filter locally); sort_by with query only sorts WITHIN each page.

## People (biggest trap)
- "my friends/roommates/coworkers/manager/sister..." = PHONE CONTACTS whose relationships list contains that word (search_contacts relationship=..., all pages). NOT Venmo friends, Splitwise groups or Gmail threads: those differ and fail grading. Contacts can have several relationships.
- Match across apps by EMAIL (venmo sender/receiver.email, splitwise members, gmail participants); texts by phone_number. A first name -> contact first_name. No contacts for a relationship -> report, don't substitute.

## Dates
- Venmo/todoist filters "YYYY-MM-DD", inclusive whole days. Datetimes ISO "YYYY-MM-DDTHH:MM:SS"; phone message windows "YYYY-MM-DD|HH:MM:SS".
- "Last N days including today" = today-(N-1)..today. "Last month" = previous calendar month. "Since 1st Jan" = YYYY-01-01.

## Venmo
- transactions = money moved (dollars). Payment requests are separate: received ones' requester = sender; status pending|approved|denied. Act only on records of the resolved people: approve/deny_payment_request(payment_request_id), like_transaction / create_transaction_comment(transaction_id, comment). show_transactions is unsorted; social_feed includes friends' transactions not involving the user.
- Pay: create_transaction(receiver_email, amount, description); request: create_payment_request(user_email, amount, description). "Split equally among roommates and me" = total/(n+1) each.

## Spotify
- duration in SECONDS. like_count/play_count are global; "songs I liked" = show_liked_songs. "My playlists" = show_playlist_library; song details need show_song. Album downloaded = all its songs downloaded.
- play_music(playlist_id|album_id|song_id) REPLACES the queue with that collection. "Play a playlist long enough for X": choose ONE playlist from the user's library (first qualifying in library order); never stitch several or use public playlists.
- Following/liking something already followed/liked returns an error message; harmless.

## Other apps
- simple_note.search_notes has no content: use show_note. Formats: "day: monday ... duration_mins: 35" blocks split by blank lines; checklists "[ ] x"/"[x] x". update_note(content=full text), keep format.
- file_system: "~/" = /home/<user>/; show_directory returns absolute paths, recursive by default; show_file gives content + created_at; media content is "binary:<hash>".
- amazon.place_order buys EVERYTHING in the cart (may already hold items); needs payment_card_id + address_id.
- gmail.send_email(email_addresses=[...], subject, body); attachments need absolute paths + file_system_access_token.

## Finishing
- supervisor.complete_task(answer=...) last. Answer = bare value (title, number, yes/no), no sentence/units; action tasks: answer None. No unrequested side effects.
