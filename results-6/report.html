What we learned

  1. Haiku 5.5 is near AppWorld's ceiling. 88% TGC from scratch, against roughly 49% for the best 2024 agents in the paper. The APIs are self-documenting (api_docs), and a current small model just reads the docs. There is little left for tools to fix, and nothing to save: a run costs less than a cent.
  2. The remaining failures are conventions, not capability. They cluster in the same scenarios in both arms and all variants (Splitwise trips from a note, "roommates", friend sync, shopping-list orders): readings of an ambiguous instruction that differ from the grader's.
  3. The experience forge found those conventions, but they only help when they are read. Haiku used the library in about half the forged runs; when it did, it followed the conventions (e.g. "roommates" → phone relationships) and passed tasks the baseline fails, but when it went straight to aw it repeated the baseline's mistakes. Net effect: none, at 12% more tokens.
  4. An explicit interface in the prompt beats library cards. With "by running Python with the aw command" in the task prompt, Haiku almost never touched the library. Neutral wording raised use to about half the runs.

Round 4's lesson holds and sharpens: a forged library pays when working knowledge of an environment cannot be guessed and the model cannot cheaply look it up. AppWorld documents itself, so the only unguessable part is the grader's conventions, and those reach the model only if it reads them.
